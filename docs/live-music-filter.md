# Фильтр новых событий: live-music-v1

Новые правила применяются только при добавлении события. `events.json` не мигрируется и не очищается по результатам аудита. Сохранённые карточки, включая будущие и ранее одобренные немузыкальные события, остаются. Обычные уточнения источника и отметки об отмене продолжают работать.

## Путь кандидата

1. Telegram / VK / MAX и загрузчики афиш создают отдельные кандидаты для каждой даты и программы.
2. `filter_new_live_music` проверяет каждый кандидат до дедупликации и сверки источников. Повторное извлечение сохранённой неподходящей программы отбрасывается без удаления старой карточки. Другая дата, другое время или другой артист того же поста не получают исключения.
3. `classify_event` из `live_music.py` возвращает `publish`, `ignore` или `review` и причину. `event_type`, флаг модели и имя участника сами по себе не подтверждают живое исполнение.
4. Только `publish` идёт дальше в обычную проверку данных. `ignore` и `review` не попадают в `events.json`, страницы, реестры, бота и рассылку. В частности, `review` нельзя случайно одобрить через прежнюю автоматическую модерацию.
5. После обработки сохранённые ID, которые исчезли при очистке или склейке, восстанавливаются из исходного снимка. Карточки, получившие обычные уточнения/отмену, сохраняют эти обновления.

## Неподходящие форматы

- Практики: женские/мужские круги, интуитивный танец, ecstatic dance, звукотерапевтические сеансы и звуковые ванны.
- Обучение, DJ-интенсивы, мастер-классы.
- Музыкальное и рок-лото, квизы, «Угадай мелодию».
- Обычное караоке посетителей, включая анонсы с ведущим в поле артиста.
- DJ-сеты, виниловые программы, музыка от диджея без отдельного живого выступления.
- Стендап, КВН, кино, лекции, экскурсии, выставки, чтения и другие немузыкальные форматы без музыкальной программы.
- Релизы и трансляции без очного выступления.

Смешанная или неполная программа отправляется на сверку. Ужин с общей припиской «живая музыка» не публикуется автоматически. Слова «круг», «камеди», «танцы», «медитативный» и электронный жанр не являются самостоятельными запретами.

Сохраняются концерты с караоке после, живой оркестр с поющим залом, живой вокал с DJ или минусовкой, инструментальные медитативные концерты, концерты с дегустацией и самостоятельные музыкальные блоки смешанных программ.

## Источники и отчёт

Инструкция модели требует сохранять основной формат, роль музыкантов и короткую цитату только о соответствующем событии. Цитата используется лишь при точном совпадении с исходным постом; весь недельный пост не передаётся как доказательство для каждой даты. Кэш старых извлечений тоже проходит общий фильтр.

Фильтр использует нормализованные текстовые признаки и контекстные исключения. Это консервативная проверка анонса, а не подтверждение фактического исполнения на сцене. Новые неизвестные и недостаточно описанные программы могут требовать ручной сверки. Концертная страница агрегатора учитывается только вместе с конкретным названием и отсутствием сигналов неподходящего формата; автоматически присвоенный тип «концерт» не разрешает публикацию DJ-вечеринки.

Каждый запуск печатает решения и сохраняет `.cache/live_music_report.json`: версия политики, решение, причина, основание и кандидат. GitHub Actions сохраняет файл в артефакте `live-music-report` на 14 дней. Это отдельный отчёт, не публичный каталог и не прежняя очередь модерации. После сверки нужно уточнить исходный анонс/правила и повторно разобрать источник; одного старого статуса approved для нового кандидата недостаточно. `--dry-run` показывает решения без записи каталога и отчёта.

Покрытие: примеры ошибок из аудита, допустимые смешанные программы, неподтверждённые цитаты, повторные извлечения, разные события одного источника, сохранение старых будущих карточек, отмены, полный проход парсера и dry run.
