# Сборщик Reels

Один концерт → MP4 1080×1920, SAR 1:1, CFR 30 fps, H.264/yuv420p, AAC, faststart. Первая фаза: 10–15 секунд, по умолчанию 10. Разрешённого звука пока нет: вся аудиодорожка цифровая тишина. Генеративных запросов, публикации и внешних сообщений в сборщике нет.

## Принятый макет

Avenir Next Demi Bold / Regular из системы А2, файл и лицо коллекции закреплены SHA-256. Винил 510 px, x=255,y=200; до текста минимум 115 px. Имя 150 px, до двух строк; рубрика 48 px; дата 64 px; площадка 52 px до двух строк; бренд/город 44/46 px внизу. Текст проявляется без перемещения и полностью виден с 2,3 с. Длинный текст даёт отказ вместо уменьшения. Отклонённый вариант с винилом 260 px не включается.

Полный исходник сохраняется в принятом режиме contain. В cover разрешено приближение до 3,5%, если защищённые области помещаются в обоих крайних состояниях. Пиксельная проверка пересечений создаёт отдельные issues для лиц, фигур, предметов, водяных знаков и текста. Проектные маски UI: верх 180 px, правая полоса с x=960, низ с y=1750; это технический профиль проекта, не заявление об одинаковом интерфейсе Instagram на всех устройствах.

17 октября отдельно утверждён `group-strip-v1`: прежний винил 510 px наверху, полный групповой снимок в полосе y=740..1253, рубрика y=1285, имя y=1360, дата y=1530, площадка y=1620, подписи y=1700. Размеры шрифтов сохраняются. Этот вариант автоматически выбирается только для широкого группового фото (отношение сторон от 1,65) и однострочных имени, рубрики и площадки. Приближения фото нет. Если текст не помещается, сохраняется стандартный кандидат с его проверками и возможным отказом; уменьшения букв или скрытой обрезки нет.

## Вход из изображений

```sh
pip install -r social/reels-requirements.txt
python -m social.reel_module --images PATH_TO_PHASE1_A2 --event EVENT_ID --output social/bundles/reels
```

`prepare_from_images(image_output,event_id,output,duration=10)` читает текущую безопасную версию через `post_phase1.get_phase1_current(approved_only=False)`. Одобрение/публикация поста не требуется. Берутся selected-source.png, анализ и event.cover, а не готовая плоская карточка с надписями. Происхождение существующей иллюстрации сохраняется. Устаревший пакет, pending, небезопасный анализ или другой формат не обходятся.

API всегда возвращает `(bundle_or_none, report)`. CLI печатает JSON; failed → код 1, готовый технический черновик или нерешённая композиция → код 0. Код 0 не означает допуск к отправке.

В версии: source.png, spec.json, reel.mp4, cover.jpg с 3 с, preview.jpg, text-layout.json, source-placement.json, composition.json, ui-preview.jpg, report.json. После технического успеха обновляется current/EVENT_ID.json. Failed/отказ без MP4 записывается отдельно в attempts; ранний отказ — errors. Повтор проверяет контрольные суммы и кэш. На недоступной файловой системе API/CLI всё равно возвращает структурированную ошибку с persistence_error.

## Отзыв и локальная очередь

`reel_delivery.record_review()` принимает реальный отдельный отзыв по принятой политике, с точными хешами файлов и фактов. Положительный отзыв требует полного просмотра, всех checks и доверенного reviewer из политики. Отзыв не переносится со старого видео, поста или шаблона. Никакой owner не генерируется.

`enqueue_project()` применяет settings, проверяет текущий А2 и карточку проекта, затем проверяет источник/факты/отмены/модерацию и историю перед идемпотентной передачей в локальную SQLite-очередь. Нужны настоящая квитанция успешного обновления источника, подтверждение live-формата и импортированная история. mtime/post_date не принимаются за свежесть. После 24 ч требуется новая проверка; перед самой отправкой потребитель обязан вызвать evaluate снова. Нового кода публикации Instagram здесь нет. Архивные фикстуры не допускаются в очередь.

## Автоматическая приёмка и граница модуля

`reel_review.review()` сначала проверяет геометрию, затем заново строит эталон утверждённой анимации и сравнивает каждый кадр конечного MP4. После успешной проверки потока отдельная мультимодальная оценка проверяет исходник, читаемый кадр из видео, UI-preview и подборку кадров движения. Модель получает статичные изображения, а непрерывность проверяет программа; это явно разделено в доказательствах. Положительный серверный отзыв требует обоих результатов и связывается с точными артефактами и фактами. Изменённый или устаревший отзыв пересоздаётся; неудачная проверка не даёт допуска.

`reel_review_provider.YandexReelVision` выполняет не более одного семантического запроса за проверку и использует явный лимит расходов с постоянным журналом. Ключи берутся из окружения. Локальный пример Helvegen прошёл проверку всех 300 кадров и реальную оценку через Yandex; это не подтверждение свежести источника или разрешение публикации.

`reel_pipeline.run_batch()` — вход для общего агента: проверенные текущие А2 → сборка → автоматическая приёмка → передача в локальную очередь. Отсутствие подтверждений источника/истории даёт записанный пропуск до дорогих операций; отклонённый кандидат заменяется другим в пределах лимитов. Сам сборщик, проверка и адаптер очереди не публикуют. Расписание, постоянное облачное хранение, обслуживание аккаунта и публикация принадлежат общему конвейеру агента.

Новая версия проверена 60 целевыми тестами локально. Предыдущий облачный запуск с 42 тестами относится к прежней версии; обновлённые workflow и код требуют отдельного облачного прогона. Итоговая приёмка всего набора «Джокер» / Helvegen / «Вечер романсов» ещё не закрыта.

## Переносимое облачное задание

```sh
python -m social.reel_job export --images PATH_TO_PHASE1_A2 --event EVENT_ID --output job
REELS_FONT=/path/on/renderer/avenir.ttc python -m social.reel_job render --job job --output result
```

Job содержит только относительные пути, исходник, винил, конфигурацию и хеши кода/данных. Системный шрифт не распространяется в пакете. Для Linux нужен доступный там разрешённый файл с закреплённым хешем; для macOS можно использовать установленный на удалённом раннере файл, если совпадают хеш и лицо. Замена шрифта требует отдельной визуальной проверки, не выполняется молча.

`.github/workflows/reels-check.yml` запускает тесты и архивный job на отдельной ветке codex/reels-reliability, без публикации и очереди. `.github/workflows/render-reel.yml` — прежний ручной низкоуровневый запуск; он сам по себе не включает автономного агента. Непрерывное обслуживание, источник фактов, отзывы и публикационный потребитель подключаются отдельно.
